# ポケカ 優勝デッキまとめ (シティリーグ / ジムバトル)

大会結果から **優勝・準優勝のデッキだけ** を自動で集めて、
8歳の子どもが一人で読めるページにして毎日更新する仕組み。

店舗ごとにページを行き来しなくても、1つのページで
「いま何が勝っているか」が分かるようにするのが目的。

---

## 1. できること

| | 中身 | 状態 |
|---|---|---|
| あたらしい じゅん | 優勝・準優勝デッキを日付の新しい順に一覧 | ✅ |
| デッキ画像 | 一覧にそのまま並べる。タップしなくても中身が見える | ✅ |
| タップ | 公式のレシピページ (実物の60枚) へ移動 | ✅ |
| どの たいかい？ | シティリーグ / ジムバトル / ぜんぶ で切り替え | ✅ |
| つよい じゅん | 直近1週間 / 1ヶ月 / 全期間の優勝回数ランキング | ✅ ジムバトルのみ |
| デッキで さがす | デッキ名のボタンで絞り込み (文字入力なし) | ✅ ジムバトルのみ |

トップには「いま いちばん つよい デッキ」(直近1週間で最も優勝しているデッキ) が出る。
日々のデッキ作りの参考にはこれが一番効く。

**シティリーグにデッキ名が付かない理由**は 2 の「デッキ名について」を参照。
名前が無くても、順位・店舗・日付とレシピへのリンクは揃っている。

## 2. 全体の流れ

```
毎日 08:00 JST  GitHub Actions が起動
        ↓
   ┌────────────────────┴────────────────────┐
   ↓                                          ↓
pokecabook (シティリーグまとめ記事)      deckindex (デッキ別ページ)
 → 日付・店舗・都道府県・順位             → デッキ名・日付・順位
 → デッキコード・公式イベントURL          → デッキコード
 → ★デッキ名は無い                       → ★店舗名は無い
   └────────────────────┬────────────────────┘
                        ↓
        デッキコードをキーに突き合わせて統合
                        ↓
   (任意) 公式イベントページでリーグ区分を補う
                        ↓
   data/pokeca/results.json に追記 (古い分は削除)
                        ↓
   site/index.html を生成 → GitHub Pages に公開
                        ↓
   子どもはホーム画面のアイコンをタップするだけ
```

`DeckResult.slot_id` は **デッキコードがあればそれ自体** を識別子にする。
公式が発行するコードは提出デッキ1つにつき1つなので、収集元が違っても
同じコードなら同じ結果を指す。これで「順位と店舗」と「デッキ名」を結び付ける。

### 収集元1: シティリーグのまとめ記事 (`sources/pokecabook.py`)

実物の構造 (archives/320777 で確認済み):

```html
<div class="entry-content">
  <h2><span id="toc1">宝島　岐阜本店（岐阜）</span></h2>
  <p><a href="https://players.pokemon-card.com/event/detail/953108/result">大会結果</a></p>
  <figure class="wp-block-gallery">
    <figure class="wp-block-image">
      <a href="...jpg"><img src="...1_1_8YGKY8-wTd9K2-8Dacc4.jpg"></a>
      <figcaption>
        <a href="https://www.pokemon-card.com/deck/confirm.html/deckID/8YGKY8-wTd9K2-8Dacc4">優勝</a>
      </figcaption>
    </figure>
    ... 準優勝 / TOP4 / TOP8 / TOP16 が続く
  </figure>
  <h2>... 次の店舗 ...</h2>
</div>
```

1記事に21店舗ぶん。各店舗に 優勝1・準優勝1・TOP4×2・TOP8×4・TOP16×8。
このうち優勝と準優勝だけを取る。

- ✅ 公式デッキコードが全エントリーに付いている。当初は公式サイトから取る
  つもりだったが、その必要が無くなった
- ✅ 公式イベントページのURLも店舗ごとに付いている
- ✅ `<span id="tocN">` で元記事の該当店舗へ直接ジャンプできる
- ❌ **デッキ名がどこにも書かれていない**。デッキは画像で示され、
  `img` の `alt` も空。文字情報は順位ラベルとデッキコードだけ

### 収集元2: デッキ別ページ (`sources/deckindex.py`)

実物の構造 (archives/122503「ポケカ【ドラパルトex】優勝デッキレシピまとめ」で確認済み):

```html
<div class="entry-content">
  <h2>ストームエメラルダ環境</h2>
  <figure class="wp-block-image">
    <img alt="【ドラパルトex】ジムバトル優勝デッキレシピ" src=".../image-132.png">
    <figcaption>
      <a href="https://www.pokemon-card.com/deck/result.html/deckID/cxxGxa-71MIig-J8cY8c/">
        8/9【日】ジムバトル優勝
      </a>
    </figcaption>
  </figure>
  ... 同じ形が数百件続く
</div>
```

1つの figure から3つが同時に取れる。

- デッキ名: `img` の `alt` にある【…】
- 開催日と大会種別: `figcaption` の「8/9【日】ジムバトル優勝」
- デッキコード: `figcaption` のリンク先

デッキ一覧は [archives/1417](https://pokecabook.com/archives/1417) にあり、
73デッキぶんのページが並んでいる。**この一覧を正として巡回する。**

RSS のカテゴリフィードは使わない。1回に10件しか返さないうえ、
「【8/10(月)】ジムバトル優勝デッキまとめ」のような日付ページが混ざり、
タイトルの【…】を拾うと日付がデッキ名になってしまうため
(実際に初回の収集で「8/10(月)」というデッキが48件できてしまった)。
一覧ページを使えば全デッキを取りこぼさず、デッキ名も一覧の表記で確定できる。

デッキ別ページは1枚 500KB 前後ある。73デッキを毎日まとめて取ると 40MB を超え、
個人ブログに対して毎日それを続けるのは行儀が悪いので、
**日ごとに25デッキずつ巡回して3日で一周する** (`--deck-batch` で変更可)。
データはマージして貯めるので、一周ぶん遅れても内容は揃う。

**ジムバトルは優勝のみ**が掲載されている。実物ページの324件すべてが
「ジムバトル優勝」で、準優勝は1件も無い。ポケカブックがジムバトルの
準優勝を公開していないため、こちらで取ることはできない。

### デッキ名について

デッキ名は上のデッキ別ページから取る。つまり:

- **ジムバトル**: デッキ名あり ✅ (ランキングも絞り込みも動く)
- **シティリーグ**: デッキ名なし ⏸

シティリーグに名前が付かないのは、デッキ別ページに載っているのが
ジムバトルの結果だけで、シティリーグのデッキコードと重ならないため
(手元の42件で照合したところ一致0件)。

デッキ名が1件も無いあいだ、子ども向けページは自動的に
**ランキングとデッキ絞り込みを隠し、新着一覧だけを表示する**。

シティリーグにも名前を付けたい場合の残る手段:

1. デッキ別ページがシティリーグの結果も載せるようになれば自動で解決する
   (パーサーは「シティリーグ優勝」形式のキャプションにも対応済み)
2. デッキコードから公式のレシピページを開き、採用カードから名前を推定する

## 3. 最初のセットアップ (親が1回だけ)

### 3-1. GitHub Pages を有効にする

リポジトリの **Settings > Pages > Build and deployment** で
Source を **GitHub Actions** に変更する。

> ⚠️ このリポジトリの Pages はポケカのページ専用にすること。
> 以前、別の用途で公開していたサイトと同じリポジトリに置いてしまい、
> そのサイトを上書きする事故を起こした。Pages は1リポジトリに1サイトしか
> 持てないので、用途の違うものを同居させない。

> ⚠️ Pages を公開にすると、URLを知っている人は誰でも見られる。
> 公開しているのは `site/` の中身だけで、リポジトリの他のファイルは含まれない。
> 家族だけで使いたい場合は、Pages を使わずに 4-2 のローカル運用にする。

### 3-2. ワークフローを手動で1回動かす

**Actions > Collect Pokeca winning decks > Run workflow**

`dry_run` を `true` にすると、保存せず収集結果だけを確認できる。
まずはこれで何件取れるか見るのがおすすめ。

### 3-3. 子どものスマホ・タブレットに登録する

公開された Pages の URL を開いて、ブラウザの共有メニューから
**「ホーム画面に追加」**。アプリのアイコンのように起動できるようになる。

## 4. コマンド

### 4-1. ふだん使うもの

```bash
python -m src.pokeca.cli collect              # 収集して results.json を更新
python -m src.pokeca.cli collect --dry-run    # 保存せず結果だけ見る
python -m src.pokeca.cli build                # site/index.html を生成

python -m src.pokeca.cli list --rank 1 --event city   # シティリーグの優勝だけ
python -m src.pokeca.cli rank --days 7 --event gym    # ジムバトルのランキング
```

収集元を片方だけ動かしたいとき:

```bash
python -m src.pokeca.cli collect --source pokecabook  # シティリーグだけ
python -m src.pokeca.cli collect --source deckindex   # デッキ別ページだけ
python -m src.pokeca.cli collect --with-league        # リーグ区分も補う(未検証)
```

### 4-1-2. デッキの中身を調べる

デッキの中身 (`decklists.json`) が貯まってから使える。

```bash
python -m src.pokeca.cli fetch-decks --limit 200   # 60枚の中身を取りに行く
python -m src.pokeca.cli fetch-cards --limit 200   # カードのテキストを取りに行く

python -m src.pokeca.cli cards ドラパルト          # 確定枠と選択枠を分けて出す
python -m src.pokeca.cli variants ドラパルト       # 型に分ける
python -m src.pokeca.cli decks-with マシマシラ     # そのカードを使うデッキ
python -m src.pokeca.cli check <デッキコード>      # 自分のデッキと見比べる
```

デッキ名・カード名は一部だけで通じる (「ドラパルト」で引ける)。

数字の読み方で気をつけること:

- 採用率は必ず「何件中の何件か」で見る。3件中3件と80件中80件は意味が違う
- 平均枚数は**入れているデッキの中での平均**。入れていないデッキを0枚として
  混ぜていない
- `check` は強い弱いを判定しない。勝っているデッキとの違いを並べるだけ

### 4-2. GitHub を使わずローカルだけで運用する場合

```bash
python -m src.pokeca.cli collect
python -m src.pokeca.cli build
open site/index.html      # ブラウザで開くだけ。ネット公開しない
```

生成される `site/index.html` は1ファイル完結 (CSS・JS・データを全部内包)。
そのままメールで送ったり、タブレットにコピーしてオフラインで開いてもよい。

### 4-3. 動作確認用

```bash
python -m src.pokeca.cli sample   # ダミーデータを入れる
python -m src.pokeca.cli build    # ページを作って見た目を確認
python -m pytest tests/test_pokeca.py -q
```

サンプルデータで生成したページには「これは練習用です」の警告が出る。

### 構造が変わってパーサーが空振りしたら

```bash
python -m src.pokeca.cli inspect --source pokecabook   # 実物を保存
```

`data/pokeca/_inspect/` に生のJSON・HTMLが落ちる。それを見て
`src/pokeca/sources/` を直し、**新しい実物で fixture を差し替えてから**
テストを通すこと。

### 想定される詰まりどころ

| 症状 | 原因の見当 |
|---|---|
| REST API が 403/404 | 対応済み。`collect` が自動で RSS → HTML に切り替える。`probe` で確認できる |
| デッキ名が日付や弾の名前になる | 日付ページを取り込んでいる。`is_plausible_deck_name()` で弾く。過去分は `collect` のたびに自動で空にされる |
| シティリーグが増えない | シーズンの合間は開催が無い (シーズン4は3〜5月)。ジムバトルは通年あるので、そちらが増えていれば正常 |
| 記事は取れるが0件 | `content.rendered` に `.entry-content` ラッパーが無い場合がある。パーサーは両対応済みだが、ギャラリー構造が変わっていないか確認 |
| 店舗名に都道府県が付く | `split_store()` の括弧パターンを確認 |
| リーグ補完が全部空 | 公式ページがJavaScript描画。`--with-league` を外して運用する (無くても困らない) |
| ランキングが同じデッキで割れる | 表記ゆれ。`data/pokeca/deck_themes.yaml` の `aliases` に追記 |
| results.json が巨大になる | ジムバトルは1日数百件出る。`--keep-days` を短くする (既定180日) |

## 5-2. 集計とデータ品質で踏んだ落とし穴

実データを見て初めて分かった不具合が続いたので、再発防止のため記録しておく。
どれもテストで固定してある。

| 症状 | 原因 | 対策 |
|---|---|---|
| ランキングに古い日付が出る | 集計の起点がデータ内の最新日だった。シティリーグはシーズンが5月で終わっているため、8月に見ても 4/30〜5/6 が「今週」になっていた | 起点を **今日** にした。該当が無ければ空で返す |
| 未来の日付が43件 | 開催日の年を記事の公開日から推定していた。デッキ別ページには前年の結果も並ぶため、8月更新のページの「8/12」を当年と判定していた | **大会結果が未来になることはない**ので、収集日を超えない範囲で一番新しい年を選ぶ |
| デッキ名が「8/10(月)」 | 日付ページを取り込み、タイトルの【…】を拾っていた | デッキ一覧ページを正として巡回する |
| デッキ名が「アビスアイ」 | 弾の名前。形はデッキ名らしく、正規表現では弾けない | デッキ一覧を正解リストとして、載っていない名前は空に戻す |
| 「ゆうしょうデッキ」だけのカード | 名前を除去したジムバトルが残った。ジムバトルは店舗名も無いので情報が残らない | 名前の無いジムバトルは捨てる (シティリーグは店舗があるので残す) |

**集計の起点は必ず「今日」にすること。** データ内の最新日を起点にすると、
収集が止まったときに古い結果を「最新」として見せてしまう。

## 5-3. デッキ画像について

一覧にデッキ画像をそのまま並べている。タップしないと中身が見えないのでは
元サイトより使いづらい、という理由。

**画像は公式が生成するPNGを使う。デッキコードから組み立てられる。**

    画像ページ https://www.pokemon-card.com/deck/thumbs.html/deckID/<コード>/
    画像本体   https://www.pokemon-card.com/deck/deckView.php/deckID/<コード>.png

`DeckResult.deck_image_url` がこれを返す。収集しなくても、デッキコードさえ
あれば全レコードに画像が付く。**デッキ名の無いシティリーグでも画像は出る**
ので、名前が取れない問題の実害はかなり小さくなった。

はじめは収集元 (`pokecabook.com`) の画像URLを拾って使ったが、
直リンクが効かず表示されなかった。`image_url` フィールドにはその名残が
入っているが、表示には使っていない。

- `loading="lazy"` で、画面に入ったぶんだけ読み込む
- 読み込めなければ `onerror` で消す。壊れたアイコンは出ず、
  カードはリンクとして機能し続ける
- ⚠️ Claude の Artifact プレビューは外部画像を CSP で止めるため、
  画像はそちらでは出ない。GitHub Pages では出る

## 5-4. デッキの中身が素のGETでは取れない件

デッキ作りの相談に答えるにはカード単位のデータが要るが、**公式のデッキページは
カード表を JavaScript で組み立てている**ため、素のGETでは取れない。

    result.html  HTTP 200 / 35,097文字 → カード表 0行
    confirm.html HTTP 200 / 33,386文字 → カード表 0行

ブラウザで保存した webarchive は74KBあり、カード表も入っていた。
**webarchive は JavaScript 実行後の DOM を保存する**ため、実際に返ってくる
HTMLとは別物だった。ここを確認せずに実装を進めてしまったのが失敗。

**教訓: 保存されたページで構造を確認するときは、それが素のレスポンスなのか
JS実行後のDOMなのかを必ず区別する。** サイズを比べれば分かる。

調べ方:

```bash
python -m src.pokeca.cli dump-official   # 素のレスポンスの中身を調査
```

### 解決: 中身は hidden の入力欄に入っていた

素のHTMLを端から出して調べたところ、**カード表は無くても、デッキの中身
そのものは hidden の入力欄に入っている**ことが分かった。

```html
<input type="hidden" name="deck_pke" value="47847_2_1-49270_4_1-45707_3_1-...">
<input type="hidden" name="deck_gds" value="46219_4_1-48679_1_1-...">
<input type="hidden" name="deck_sup" value="46824_4_1-46227_2_1-...">
<input type="hidden" name="deck_sta" value="46041_2_1">
<input type="hidden" name="deck_ene" value="46116_8_1-46119_4_1-46121_4_1">
```

`カードID_枚数_?` を `-` で連ねた形。欄の名前が区分に対応する。

| 欄 | 区分 |
|---|---|
| `deck_pke` | ポケモン |
| `deck_tool` | ポケモンのどうぐ |
| `deck_gds` | グッズ |
| `deck_sup` | サポート |
| `deck_sta` | スタジアム |
| `deck_ene` | エネルギー |
| `deck_tech` / `deck_ajs` | **中身が入った実物をまだ見ていない**。区分名は仮 |

カード名・収録セット・番号・カード画像は、同じHTMLのインラインJSにある。

```js
PCGDECK.searchItemName[47847]='メガガルーラex(M1S 051/063)';
PCGDECK.searchItemNameAlt[47847]='メガガルーラex';
PCGDECK.searchItemCardPict[47847]='/assets/images/card_images/large/M1S/047847_P_....jpg';
```

実物 (`ngHLgL-pA4GKN-9gniQn`) で枚数の合計は60ちょうど、種類は27で、
`searchItemName` の件数と一致した。**1回のGETで60枚そろう。**
ヘッドレスブラウザは要らなかった。

カード詳細ページ (`card-search/details.php/card/<ID>/`) は最初から素のGETで
読める。実機で `fetch-decks` / `fetch-cards` とも 5/5 成功を確認済み。

**教訓: 「JSが組み立てている」と分かった時点で諦めない。組み立てる元の
データはページのどこかにある。** input・textarea・インラインJSを端から
出せば見つかる。`dump-official` がそれをやる。

### 調査用ワークフロー

開発機から公式サイトへは接続できないため、実物のレスポンスは Actions でしか
見られない。`.github/workflows/investigate.yml` が調査専用で、
`.github/investigate-trigger` を書き換えて push すると走る。
権限は `contents: read` だけなので、収集にも公開にも触れない。
**調査が終わったらこのワークフローごと消してよい。**

## 6. 収集が止まったときの通知

サイト構造が変わると、エラーは出ないのにデータだけ増えない状態になりやすい。
これを検知するため、毎日 `healthcheck` が走る。

最新の開催日が10日以上前になると、自動で `pokeca-alert` ラベル付きの
Issue が立つ (同じ Issue が開いているあいだは重複して立てない)。

```bash
python -m src.pokeca.cli healthcheck --max-age-days 10
```

## 7. 方針として決めたこと

### 著作権・マナー

- **転載しない**。保存するのは「日付・店舗・順位・デッキ名・デッキコード・
  元記事URL」という事実データとリンクだけ。記事本文もレシピ画像もコピーしない。
  デッキの中身は必ず公式または元サイトを開いて見る導線にしている
- **robots.txt を必ず確認**してから取得する (`src/pokeca/http.py`)。
  禁止されていれば取得しない
- **同一ホストへのアクセスは1.5秒あける**。1日1回の巡回なので相手への負荷はごく小さい。
  デッキ別ページは1枚に数百件入っているので、ページを1枚ずつ開くより
  REST API でまとめて取るほうが相手にも優しい
- User-Agent に用途と連絡先を明記している

### プライバシー

- **プレイヤー名は保存しない**。公開ページに他人の名前が載るのを避けるため。
  順位とデッキの対応だけ分かれば目的は達成できる

### 子ども向けUIの設計意図

- **文字入力をさせない**。操作は大きなボタンのタップだけ
- **UIの文言はひらがな**。日付も「5がつ6にち」形式
- デッキ名はカタカナが多くそのまま読めるので、文字を大きくして主役にする
- ひらがなが単語の途中で折り返されると読みにくいので `word-break: keep-all`
- タップ領域は最低52px。指が大きくズレても押せるように
- デッキごとに色と絵文字を固定 (`data/pokeca/deck_themes.yaml`)。
  文字を読まなくても色で見分けられる
- 一覧は**大会種別ごとに**新しい順で300件まで。ジムバトルは件数が桁違いに多いため、
  全体の新しい順で切るとシティリーグが一覧から消えてしまう

## 8. ファイル構成

```
src/pokeca/
├── models.py           # DeckResult (共通データモデル) と正規化
├── store.py            # results.json の読み書き・マージ・期限切れ削除
├── aggregate.py        # ランキング集計
├── site.py             # 子ども向けHTMLの生成
├── http.py             # robots.txt 遵守・アクセス間隔制御
├── cli.py              # コマンド
└── sources/
    ├── pokecabook.py   # シティリーグまとめ記事 (順位・店舗・デッキコード)
    ├── deckindex.py    # デッキ別ページ (デッキ名・ジムバトル優勝)
    └── official.py     # 公式プレイヤーズクラブ (リーグ区分の補完のみ)

data/pokeca/
├── results.json        # 収集結果 (これが資産)
├── deck_themes.yaml    # デッキの色・絵文字・表記ゆれ統合
└── _inspect/           # inspect コマンドの出力 (gitignore)

site/index.html         # 生成物。GitHub Pages で公開される

tests/
├── test_pokeca.py                            # パーサー・マージ・集計のテスト
└── fixtures/
    ├── pokecabook_city_league.html           # 実物HTMLの抜粋
    ├── pokecabook_deck_page.html             # 実物HTMLの抜粋
    └── pokecabook_deck_catalog.html          # 実物HTMLの抜粋
```

情報源を足したいときは `sources/` にファイルを1つ追加して
`cli.py` の `SOURCE_NAMES` に登録すれば済むようにしてある。
